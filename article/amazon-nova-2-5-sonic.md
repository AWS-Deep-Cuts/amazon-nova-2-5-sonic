# はじめに

Amazon Nova 2.5 Sonic は、人の声を聞き取り、声で答える「speech-to-speech（音声から音声へ）」の基盤モデルです。2026 年 10 月に Amazon Bedrock で一般提供が始まりました。

この記事では、Nova 2.5 Sonic の仕組みを前提知識から解説したうえで、ローカル PC 上のプレイグラウンドで 8 つの観点を確認するハンズオンを紹介します。あわせて、ハンズオンを作る過程で実際に試して分かったことも紹介します。

# 1. Amazon Nova 2.5 Sonic とは

## 1.1 従来の音声対話との違い

音声で会話する AI は、これまで次の 3 つの処理を別々のサービスで行い、それらを組み合わせて作るのが一般的でした。

```text
ユーザーの音声 → 音声認識（Amazon Transcribe など）→ テキスト
             → 応答の生成（LLM）                → テキスト
             → 音声合成（Amazon Polly など）      → AI の音声
```

Nova 2.5 Sonic は、この 3 つの処理を 1 つのモデルで行います。従来の構成との違いを整理します。

| 項目 | 従来の構成 | Nova 2.5 Sonic |
| -- | -- | -- |
| 構成 | 3 つのサービスを組み合わせる | 1 つのモデルで完結する |
| 発話の終わりの判定 | アプリ側で制御する | モデルが行う |
| AI の発話中の割り込み（barge-in） | アプリ側で実装する | モデルが対応する |

## 1.2 主な仕様

主な仕様は次の通りです。

| 項目 | 内容 |
| -- | -- |
| モデル ID | `amazon.nova-2-5-sonic` |
| API | `InvokeModelWithBidirectionalStream`（双方向ストリーミング） |
| 音声の形式 | 16bit・モノラルの PCM 音声（入力・出力とも 8kHz／16kHz／24kHz） |
| 1 回の接続の上限 | 8 分 |
| 対応リージョン | 米国東部（バージニア北部）、米国西部（オレゴン）、欧州（ストックホルム）、アジアパシフィック（東京） |
| 対応言語 | 英語、スペイン語、フランス語、イタリア語、ドイツ語、ポルトガル語、ヒンディー語 |

2026 年 10 月時点で、日本語は対応言語に含まれていない点に注意してください。

前世代の Nova 2 Sonic とは、API・声の種類・対応言語が共通です。Nova 2.5 Sonic では、指示への忠実さ、ツール呼び出しの精度、応答が返るまでの速さが改善されています。

## 1.3 双方向ストリーミングの仕組み

Nova 2.5 Sonic の API は、リクエストを 1 回送って応答を 1 回受け取る形式ではありません。1 本の接続を開いたままマイクの音声を送り続け、同時に AI の音声とテキストを受け取り続けます。

やり取りは「イベント」と呼ばれる小さなメッセージの組み合わせで行います。アプリから送る主なイベントは次の通りです。

```text
sessionStart            … 会話全体の設定（応答の長さ、発話の終わりを判定する感度など）
promptStart             … AI の声（voiceId）、使用できるツールの定義
contentStart～contentEnd … システムプロンプト（AI への指示）
contentStart            … マイク音声の送信開始（会話中は開いたまま）
  audioInput × N        … マイクの音声を少しずつ送り続ける
contentEnd → promptEnd → sessionEnd … 会話の終了
```

Nova 2.5 Sonic からは、文字（ユーザーの発話の認識結果と AI の応答。`textOutput`）、AI の音声（`audioOutput`）、ツールの呼び出し要求（`toolUse`）などのイベントが返ってきます。

## 1.4 主な機能

ハンズオンで扱う主な機能は次の通りです。

| 機能 | 内容 |
| -- | -- |
| ターンテイキング | ユーザーの発話の終わりをモデルが判定し、応答を始めます |
| 割り込み（barge-in） | AI の発話中にユーザーが話し始めると、AI は発話を止めます |
| テキスト入力（Cross-modal input） | 音声だけでなく、テキストも会話の入力として送れます |
| Tool use | 会話の途中で外部の関数（ツール）の呼び出しを要求し、アプリから返された結果を使って答えます |
| 声（voiceId）の選択 | `matthew` と `tiffany` は、1 つの声ですべての対応言語を話せる「ポリグロットボイス」です |

# 2. このハンズオンで作るもの

ローカル PC 上に、Nova 2.5 Sonic と音声で会話できるプレイグラウンドを構築します。AWS リソースの作成は不要です。

プレイグラウンドは次の 3 つで構成されます。

| 構成要素 | 役割 |
| -- | -- |
| index.html（ブラウザ） | マイクの音声を送り、AI の音声を再生します |
| server.py（中継サーバー） | ブラウザと Nova 2.5 Sonic の間でイベントを中継します。ツール（天気の取得）もここで実行します |
| Nova 2.5 Sonic（Amazon Bedrock） | 音声を理解し、音声で応答します |

ブラウザから直接 Bedrock を呼び出さずに中継サーバーを置いているのは、AWS の認証情報をブラウザに渡さないためです。

当初は、CloudShell 上のスクリプトからテキストで話しかけ、AI の音声応答をファイルに保存して確認する形式で作成していました。しかし、割り込みなどの特性はリアルタイムで会話しないと体験できないため、マイクで会話するプレイグラウンドの形式に変更しました。

プロンプトや設定を書き換えながら、次の 8 つの観点を確認します。

1. 通常のプロンプトでは AI が自分から話しかけてこないこと
2. テキスト入力を合図に、AI から先に話しかけさせられること
3. 話者（voiceId）を変更できること
4. 言語を変更できること（ポリグロットボイス）
5. ターンテイキングと割り込み（barge-in）が自然に動作すること
6. 話し方の抑揚・テンションが AI の応答に影響するか（検証）
7. Tool use で外部の情報（今日の天気）を取得できること
8. AI の話す速さを指定する設定が無いこと（制約の理解）

# 3. 前提条件

- AWS アカウントがあり、`bedrock:InvokeModel` の権限を持つ IAM ユーザーまたはロールを使えること
- AWS CLI などで認証情報を設定済みであること（IAM Identity Center にも対応しています）
- Python 3.12 以上がインストールされていること
- マイク付きの PC と、Chrome または Edge があること

> Amazon Bedrock のモデルは、2025 年 10 月以降、コンソールでの利用申請なしで使えるようになりました。利用の可否は IAM のポリシーで制御します。

# 4. ハンズオン

詳細な手順は GitHub の README にまとめています。ここでは、各ステップの流れと学習ポイントを紹介します。

## 4.1 セットアップ

リポジトリをクローンし、`setup.py` を実行します。

```bash
git clone https://github.com/AWS-Deep-Cuts/amazon-nova-2-5-sonic.git
cd amazon-nova-2-5-sonic/hands-on
python setup.py
```

`setup.py` は以下を行います。

1. Python のバージョンと依存パッケージを確認する
2. AWS の認証情報を確認する
3. Nova 2.5 Sonic を呼び出せるか（権限・リージョン）を確認する
4. Nova 2.5 Sonic が「Welcome to AWS Deep Cuts!」と一言あいさつする
5. 中継サーバーを起動する

問題があれば、原因と対処方法を表示して停止します。起動後、`hands-on/index.html` をブラウザで開きます。

**学習ポイント**:

- Nova 2.5 Sonic の双方向ストリーミングは、Python では boto3 ではなく新しい SDK（`aws-sdk-bedrock-runtime`）から呼び出します。この SDK は Python 3.12 以上が必要です。
- この SDK は、標準の設定では IAM Identity Center（SSO）の認証情報を読み込めません。ハンズオンでは、boto3 と同じ方法で認証情報を取得するようにしています。

## 4.2 観点 1・2: AI から話しかけさせる

デフォルトのシステムプロンプトで会話を開始し、何も話さずに待ちます。AI は何も話しません（観点 1）。

次に、AI に挨拶を指示したシステムプロンプトで会話を開始し、テキスト入力欄から `Start` と送信します。すると、AI がシステムプロンプトで指定した挨拶を話し始めます（観点 2）。

**学習ポイント**:

- Nova 2.5 Sonic は、ユーザーの入力を受けて初めて応答を生成します。システムプロンプトに「先に話して」と書くだけでは、AI は話し始めません。筆者も当初は、システムプロンプトだけで実現できると考えていました。
- 発話の内容はシステムプロンプトで、話し始めるタイミングはテキスト入力で決まります。このハンズオンでは、この使い方を「Model-start-first」と呼んでいます。`setup.py` のあいさつも、この仕組みを利用しています。

## 4.3 観点 3・4: 声と言語を変える

設定の `voiceId` を `matthew`、`tiffany`、`amy` の順に変更し、声の違いを聴き比べます（観点 3）。続いて、`matthew` のまま、システムプロンプトで応答する言語をスペイン語、日本語の順に指定します（観点 4）。

**学習ポイント**:

- 声（voiceId）は会話の開始時に決まり、会話の途中では変更できません。
- `matthew` と `tiffany` は、声を変えずに 7 つの対応言語を話せます。一方、日本語は対応言語ではありません。

## 4.4 観点 5: ターンテイキングと割り込み

発話の終わりを判定する感度（`endpointingSensitivity`）を `LOW` と `HIGH` で切り替え、間を空けながら話しかけます。次に、AI が長い話をしている途中で割り込みます（観点 5）。

**学習ポイント**:

- 感度を `LOW` にすると、長めの間を空けても発話の終わりまで待ちます。`HIGH` にすると、短い間でも応答を始めます。考えながら話すユーザーが相手なら `LOW`、テンポを重視する場面なら `HIGH` が向いています。
- 割り込まれると、Nova 2.5 Sonic は応答の生成を止め、そのことを通知します。ただし、ブラウザが受信済みの音声は、対策をしないとそのまま鳴り続けます。音声は実際の再生より速く届くためです。プレイグラウンドでは、通知を受けた時点で再生待ちの音声を破棄しています。

## 4.5 観点 6: 声の抑揚は応答に影響するか

前世代の Nova 2 Sonic のユーザーガイドには、「入力音声の韻律（prosody）に応じて応答の話し方を調整する」という記載があります。そこで、同じ質問を普通のトーン、高いテンション、疲れた小声の 3 通りで投げかけてみました（観点 6）。

筆者が試した限り（ブラウザの自動音量調整がオンの状態）では、どの話し方に対しても、AI は同じ文を同じ調子で返しました。

**学習ポイント**:

- この機能を有効にする設定は無く、筆者が確認した範囲では、Nova 2.5 Sonic の発表資料にも記載がありません。アプリを設計する際は、話し方への適応を前提にしないほうが安全です。
- ブラウザは標準で、マイクの音量を自動でそろえます。そのため、声の大小の違いはモデルに届く前に小さくなります。プレイグラウンドでは、この処理をオフにして比較できるようにしています。

## 4.6 観点 7: Tool use で天気を取得する

Tool use を有効にして、英語で天気を尋ねます。AI が天気取得ツールを呼び出し、気象庁 API から取得した予報を音声で伝えます（観点 7）。

**学習ポイント**:

- ツールを呼び出すタイミングと引数はモデルが判断します。アプリはツールを実行し、その結果をモデルに返します。
- ツールの入力形式（`inputSchema`）の書き方は、Converse API と異なります。オブジェクトのまま渡していたときは、Tool use を有効にすると「リクエストが不正」というエラーになりました。AWS の公式サンプルでは JSON を文字列に変換して渡しており、プレイグラウンドもこの形式に修正しています。

## 4.7 観点 8: 発話スピードの制御

デフォルトのシステムプロンプトと、「ゆっくり話す」よう指示したシステムプロンプトで、同じ質問への応答を聴き比べます（観点 8）。

**学習ポイント**:

- Nova 2.5 Sonic には、話す速さを指定する設定がありません。公式のプロンプトガイドにも、声のパラメータは直接制御できないと書かれています。
- システムプロンプトで調整できるのは、応答の長さや言葉遣いです。

# 5. クリーンアップ

ターミナルで Ctrl+C を押し、中継サーバーを停止します。

Nova 2.5 Sonic は Bedrock のオンデマンド API のため、削除が必要な AWS リソースはありません。料金は、使用した分（音声・テキストのトークン数）だけ発生します。

# 6. 学んだこと

このハンズオンで分かった Nova 2.5 Sonic の特徴を整理します。

- **1 つのモデルで会話が完結する**: 音声認識・応答の生成・音声合成に加え、発話の終わりの判定や割り込みへの対応までをモデルが担います。
- **AI は自分から話し始めない**: AI から話しかけるには、アプリがテキスト入力で合図を送る必要があります。
- **アプリ側の役割も残る**: 割り込み時の再生停止、ツールの実行、エラーの表示などは、アプリ側で実装する必要があります。
- **ドキュメントの記載は自分で確かめる**: 話し方に応じた応答の変化は、試した限りでは確認できませんでした。マイクの自動音量調整のように、アプリ側の設定が結果に影響することもあります。
- **日本語は対応言語に含まれていない**: 国内向けのサービスで利用する場合は注意が必要です。
- **接続は 8 分まで**: 1 回の接続は 8 分で切断されます。長い会話を続けるには、接続をつなぎ直す仕組みが必要です。

Nova 2.5 Sonic を使うと、複数のサービスを組み合わせることなく、音声で自然に会話する AI を作れます。語学の練習相手や問い合わせの一次対応など、リアルタイムの音声対話が求められる場面で活用できます。ぜひハンズオンで、実際に話しかけて体験してみてください。
